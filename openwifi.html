1. 概述与背景

1.1 什么是 TIP OpenWiFi

TIP OpenWiFi 是由 Telecom Infra Project (TIP) 旗下的 Open Converged Wireless (OCW) 项目组于 2021 年 5 月推出的开源、社区驱动、解耦的企业级 Wi-Fi 软件系统。 它是 TIP OpenLAN 工作组孵化的首个开源项目，核心使命是"让优质 Wi-Fi 体验民主化" (Democratize Premium Wi-Fi Experiences)。

OpenWiFi 被业界描述为 "全球首个 CI/CD 开源 Wi-Fi 生态系统"，具备每日构建 (Nightly Build) 和自动化 RF 暗室测试能力。

OpenWiFi 将无线通信领域 "Open RAN" 的理念引入 Wi-Fi 世界——通过软硬件完全解耦，打破传统闭源厂商锁定，实现控制平面与数据平面的彻底分离。

3. CloudSDK 云控制器

CloudSDK 是 OpenWiFi 的云端管控核心，采用微服务架构，通过 Docker Compose 或 Helm Charts 在云环境中部署。 所有微服务均通过 OpenAPI (RESTful) 定义北向接口，使用 Kafka 消息队列进行内部通信。

4. AP 固件与 NOS

4.1 APNOS 概述

OpenWiFi 接入点运行 APNOS (AP Network Operating System)，基于 OpenWrt 构建， 专门针对企业级 Wi-Fi 场景进行深度定制和优化。固件通过双 Bank Bootloader 实现安全升级，升级失败自动回退。

5. uCentral 通信协议

uCentral 是 OpenWiFi 定义的 AP 设备与云控制器之间的标准管理协议，是实现多厂商互操作性的核心基础。 协议基于 JSON 数据模型，通过 WebSocket + 双向 TLS (DigiCert 证书) 确保安全通信。

5.1 协议规格

特性描述
传输层WebSocket (端口 15002)
安全层双向 TLS (DigiCert 设备证书)
数据格式JSON
设备标识每台 AP 具有唯一序列号 ID
配置模式数据模型驱动，基于设备能力协商
配置一致性配置变更生成唯一哈希值，设备上报状态时校验

5.3 协议消息格式

uCentral 使用 JSON-RPC 2.0 风格的消息结构。所有消息包含统一的信封格式， 通过 method 字段区分命令类型，params 承载具体的配置或状态数据。

核心命令类型

命令描述触发方
configure下发完整设备配置 JSON控制器 →AP
reboot重启设备控制器 →AP
factory恢复出厂设置控制器 →AP
upgrade触发固件升级 (指定 URL)控制器 →AP
leds控制设备 LED 指示灯 (定位用)控制器 →AP
trace开启远程抓包调试控制器 →AP

telemetry定期上报遥测数据AP →控制器

crashlog上报崩溃日志AP →控制器 (异常后)

5.4 数据模型详解 (wlan-ucentral-schema)

OpenWiFi 的完整数据模型定义在 GitHub 仓库 Telecominfraproject/wlan-ucentral-schema 中， 由 JSON Schema 和 ucode 模板 (.utpl) 两类文件组成。

数据模型顶层结构

  • configuration.json — 设备配置根
  • ├── unit — 设备基础信息 {name, location, timezone, hostname}
  • ├── interfaces[] — 接口配置数组
    • ├── WAN {role: upstream, ipv4, vlan[]}
    • ├── LAN {role: downstream, dhcp, ssids[]}
    • └── ssids[]
      • ├── wifi-bands[]: 2G / 5G / 6G
      • ├── bss-mode: ap / wds-ap / wds-sta / mesh
      • ├── encryption: proto + key + ieee80211w + radius
      • ├── roaming: 802.11k / 802.11v / 802.11r
      • ├── rates: beacon + multicast (kbps)
      • ├── rrm: load-balance + neighbor-reporting
      • └── qos: wmm + dscp-trust
  • ├── services — 系统服务
    • ├── lldp — 邻居发现
    • ├── ssh — 远程管理
    • ├── ntp — 时间同步
    • ├── igmp — 组播
    • ├── rtty — 远程终端
    • ├── mdns — 服务发现
    • ├── radius-proxy — RADIUS 代理
    • ├── wifi-steering — 频段引导
    • └── captive — 强制门户
  • ├── metrics — 遥测策略
    • ├── statistics — SSID / 客户端 / LLDP 统计
    • ├── healthchecks — CPU / 内存 / 温度 / 连通性
    • ├── wifi-frames — 802.11 管理帧捕获
    • ├── dhcp-snooping — IP-MAC 绑定表
    • └── crashlogs — 崩溃诊断数据
  • └── config-raw — 原始 UCI 透传命令

UCI 渲染机制

uCentral Agent 接收到 JSON 配置后，通过 ucode 模板 将 JSON 数据渲染为 UCI (Unified Configuration Interface) 批次命令，这是 OpenWrt 的标准配置机制：

JSON →UCI 渲染流程
# Step 1: uCentral Agent 接收 JSON 配置 INPUT: {"unit":{"name":"AP-01","location":"Floor-3"},...} # Step 2: ucode 模板渲染 (wlan-ucentral-schema/*.utpl) # 模板示例 — /usr/share/ucentral/unit.utpl: {% = let cfg = ctx.unit; {% = uci.set('system.@system[0].hostname', cfg.name); {% = uci.set('system.@system[0].location', cfg.location); {% = uci.set('system.@system[0].timezone', cfg.timezone); # Step 3: 生成 UCI 批次命令 uci set system.@system[0].hostname='AP-01' uci set system.@system[0].location='Floor-3' uci set wireless.@wifi-iface[0].ssid='Corporate-WiFi' uci set wireless.@wifi-iface[0].encryption='sae' uci commit wireless reload_config # Step 4: procd 检测配置变更，重启相关服务 (hostapd 等)

配置哈希校验机制

每次下发配置时，控制器会附带一个 MD5 配置哈希值。AP 应用配置后， 将自身计算的实际哈希值与控制器下发的哈希值进行比对：

Hash Comparison Flow
Controller: config_hash = md5(config_json) →下发配置 + hash (via WebSocket) AP: received_json →apply_config() actual_hash = md5(applied_config) if actual_hash == received_hash: →上报 state: "configured", hash: actual_hash else: →上报 state: "mismatch", hash: actual_hash →触发控制器重新下发全量配置

7. WiFi 7 与 OpenWiFi 4.0

OpenWiFi 4.0 是 TIP OpenWiFi 工作组于 2025 年发布的重大版本更新， 首次引入对 IEEE 802.11be (WiFi 7) 的全面支持，标志着开源 Wi-Fi 系统正式进入超高速时代。

7.1 WiFi 7 关键新特性

特性技术细节收益
MLO · 多链路操作 终端可同时在 2.4/5/6 GHz 多频段上收发数据 ↑ 吞吐量 · ↓ 延迟 · ↑ 可靠性
4096-QAM 调制阶数从 1024-QAM 提升至 4096-QAM 单流速率提升约 20%
320 MHz 信道 6GHz 频段支持超宽信道 理论峰值速率达 46 Gbps
Preamble Puncturing 允许在有干扰的子信道上打孔传输 提高频谱利用率
Multi-RU 单用户可分配多个资源单元 提升频谱调度灵活性
Multi-AP Coordination 多 AP 协同传输 (C-OFDMA, C-SR) 减少 AP 间干扰

7.2 OpenWiFi 4.0 架构增强

  • APNOS 内核升级至 OpenWrt 23.05+，带来更好的安全性和稳定性
  • 新增 WiFi 7 驱动框架与 HAL 硬件抽象层，支持多代芯片平台
  • CloudSDK 新增 MLO 策略管理与 WiFi 7 RRM 射频优化引擎
  • 支持 6GHz AFC (自动频率协调) 监管合规
  • WiFi 7 性能自动化 CI 测试框架，确保每夜构建质量
  • 向下兼容 WiFi 6/6E/5/4 的 AP 和客户端设备

13.4 案例四：Java REST API 自动化配置

通过 CloudSDK 的 OpenAPI 北向接口，使用 Java 标准 HTTP 客户端即可实现 AP 自动化管理。

Java Automation -- OpenWiFiManager.java
// OpenWiFi CloudSDK REST API Java client import java.net.http.*; import java.net.URI; import com.google.gson.*; public class OpenWiFiManager { private final HttpClient client = HttpClient.newHttpClient(); private final String baseUrl = "https://controller:16002"; private final String token = "your-api-token"; public String getDevices() throws Exception { HttpRequest req = HttpRequest.newBuilder() .uri(URI.create(baseUrl + "/api/v1/devices")) .header("Authorization", "Bearer " + token) .GET().build(); return client.send(req, HttpResponse.BodyHandlers.ofString()).body(); } // Configure device with WPA3 SSID public String configureDevice(String serial) throws Exception { JsonObject config = new JsonObject(); JsonObject unit = new JsonObject(); unit.addProperty("name", "Office-AP-01"); config.add("unit", unit); JsonObject ssid = new JsonObject(); ssid.addProperty("name", "Enterprise-WPA3"); JsonArray bands = new JsonArray(); bands.add("5G"); bands.add("2G"); ssid.add("wifi-bands", bands); ssid.addProperty("bss-mode", "ap"); JsonObject enc = new JsonObject(); enc.addProperty("proto", "wpa3"); enc.addProperty("ieee80211w", "required"); ssid.add("encryption", enc); JsonArray ssids = new JsonArray(); ssids.add(ssid); JsonObject iface = new JsonObject(); iface.add("ssids", ssids); JsonArray interfaces = new JsonArray(); interfaces.add(iface); config.add("interfaces", interfaces); JsonObject body = new JsonObject(); body.add("configuration", config); HttpRequest req = HttpRequest.newBuilder() .uri(URI.create(baseUrl + "/api/v1/device/" + serial + "/configure")) .header("Authorization", "Bearer " + token) .header("Content-Type", "application/json") .POST(HttpRequest.BodyPublishers.ofString(body.toString())) .build(); return client.send(req, HttpResponse.BodyHandlers.ofString()).body(); } public static void main(String[] args) throws Exception { OpenWiFiManager mgr = new OpenWiFiManager(); System.out.println(mgr.getDevices()); System.out.println(mgr.configureDevice("AABBCCDDEEFF")); } }
