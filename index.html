1. 概述与背景

1.1 什么是 TIP OpenWiFi

TIP OpenWiFi 是由 Telecom Infra Project (TIP) 旗下的 Open Converged Wireless (OCW) 项目组于 2021 年 5 月推出的开源、社区驱动、解耦的企业级 Wi-Fi 软件系统。 它是 TIP OpenLAN 工作组孵化的首个开源项目，核心使命是"让优质 Wi-Fi 体验民主化" (Democratize Premium Wi-Fi Experiences)。

OpenWiFi 被业界描述为 "全球首个 CI/CD 开源 Wi-Fi 生态系统"，具备每日构建 (Nightly Build) 和自动化 RF 暗室测试能力。

OpenWiFi 将无线通信领域 "Open RAN" 的理念引入 Wi-Fi 世界——通过软硬件完全解耦，打破传统闭源厂商锁定，实现控制平面与数据平面的彻底分离。

1.2 项目发展里程碑

3. CloudSDK 云控制器

CloudSDK 是 OpenWiFi 的云端管控核心，采用微服务架构，通过 Docker Compose 或 Helm Charts 在云环境中部署。 所有微服务均通过 OpenAPI (RESTful) 定义北向接口，使用 Kafka 消息队列进行内部通信。

3.1 微服务组件详解

微服务全称功能
OWGWOpenWiFi Gateway设备网关核心，管理与 AP 的 uCentral 协议 WebSocket 通信
OWSECOpenWiFi Security基于 RBAC 的角色访问控制，用户认证与授权
OWFMSOpenWiFi Firmware Management固件版本管理与 OTA 升级编排，支持分批灰度发布
OWPROVOpenWiFi Provisioning设备零接触配置 (ZTP)，证书管理与配置下发
OWANALYTICSOpenWiFi Analytics遥测数据分析、可视化与告警
OWSUBOpenWiFi Subscription用户/租户订阅管理，多租户隔离

4. AP 固件与 NOS

4.1 APNOS 概述

OpenWiFi 接入点运行 APNOS (AP Network Operating System)，基于 OpenWrt 构建， 专门针对企业级 Wi-Fi 场景进行深度定制和优化。固件通过双 Bank Bootloader 实现安全升级，升级失败自动回退。

5. uCentral 通信协议

uCentral 是 OpenWiFi 定义的 AP 设备与云控制器之间的标准管理协议，是实现多厂商互操作性的核心基础。 协议基于 JSON 数据模型，通过 WebSocket + 双向 TLS (DigiCert 证书) 确保安全通信。

5.1 协议规格

特性描述
传输层WebSocket (端口 15002)
安全层双向 TLS (DigiCert 设备证书)
数据格式JSON
设备标识每台 AP 具有唯一序列号 ID
配置模式数据模型驱动，基于设备能力协商
配置一致性配置变更生成唯一哈希值，设备上报状态时校验

5.2 工作流程

uCentral Protocol Flow
[1] AP 上电 → 发起 WebSocket 连接 (携带设备证书) [2] 控制器验证证书 → 建立双向 TLS 安全通道 [3] AP 上报设备能力 (Capability Report) [4] 控制器根据设备能力下发配置 (Configuration) [5] AP 定期上报状态 (Status / Health / Telemetry) [6] 配置变更时 → 控制器 PUSH 新配置
🔄

6. OpenSync 融合层

OpenSync 是 OpenWiFi 架构中的网关/路由/设备固件中间层，最初由 Plume 开发并贡献给 TIP 社区。 其核心价值在于在 Qualcomm、Broadcom 等不同芯片平台之上提供统一管理接口，实现芯片平台抽象。

6.1 架构位置

7. WiFi 7 与 OpenWiFi 4.0

OpenWiFi 4.0 是 TIP OpenWiFi 工作组于 2025 年发布的重大版本更新， 首次引入对 IEEE 802.11be (WiFi 7) 的全面支持，标志着开源 Wi-Fi 系统正式进入超高速时代。

7.1 WiFi 7 关键新特性

特性技术细节收益
MLO · 多链路操作 终端可同时在 2.4/5/6 GHz 多频段上收发数据 ↑ 吞吐量 · ↓ 延迟 · ↑ 可靠性
4096-QAM 调制阶数从 1024-QAM 提升至 4096-QAM 单流速率提升约 20%
320 MHz 信道 6GHz 频段支持超宽信道 理论峰值速率达 46 Gbps
Preamble Puncturing 允许在有干扰的子信道上打孔传输 提高频谱利用率
Multi-RU 单用户可分配多个资源单元 提升频谱调度灵活性
Multi-AP Coordination 多 AP 协同传输 (C-OFDMA, C-SR) 减少 AP 间干扰

7.2 OpenWiFi 4.0 架构增强

  • APNOS 内核升级至 OpenWrt 23.05+，带来更好的安全性和稳定性
  • 新增 WiFi 7 驱动框架与 HAL 硬件抽象层，支持多代芯片平台
  • CloudSDK 新增 MLO 策略管理与 WiFi 7 RRM 射频优化引擎
  • 支持 6GHz AFC (自动频率协调) 监管合规
  • WiFi 7 性能自动化 CI 测试框架，确保每夜构建质量
  • 向下兼容 WiFi 6/6E/5/4 的 AP 和客户端设备

8. 多厂商互操作性

这是 OpenWiFi 区别于所有闭源方案的最核心价值——同一套 CloudSDK 控制器可以管理来自不同硬件厂商的 AP，实现真正的混合部署。

8.1 互操作架构

同一套 CloudSDK 控制器 ├── 厂商 A 的 AP (WiFi 6) ├── 厂商 B 的 AP (WiFi 6E) ├── 厂商 C 的 AP (WiFi 7) └── 厂商 D 的 AP (WiFi 5) ↓ 统一的 uCentral 协议 统一的配置模型 统一的遥测格式

8.2 认证设备生态
