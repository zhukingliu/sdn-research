1. 概述与背景

1.1 什么是 gNMI

gNMI (gRPC Network Management Interface) 是由 Google 与 OpenConfig 工作组联合开发的新一代网络管理协议。使用 gRPC (基于 HTTP/2) 作为传输层，Protocol Buffers (protobuf) 作为二进制序列化格式，为网络设备提供统一的配置管理与状态监控接口。

gNMI 被设计为"单一协议解决 SNMP 监控低效 + NETCONF 流式遥测缺失"困境，是云原生网络的基石协议。

1.2 设计动机

痛点 (传统协议)gNMI 解决方案
SNMP 轮询效率低、不支持配置Push-based 流式遥测 + Set() 配置操作
NETCONF 仅支持 XML 轮询Protobuf 二进制编码 + 订阅式推送
厂商私有 MIB 碎片化OpenConfig 统一 YANG 模型
缺乏实时性亚秒级 ON_CHANGE 推送
带宽和 CPU 开销高gRPC/HTTP2 多路复用 + Protobuf 压缩 (~60% 带宽节省)

3. 四大 RPC 操作详解

操作用途Proto 字段
Capabilities发现设备支持的 YANG 模型、编码格式、gNMI 版本、扩展能力CapabilityRequest/CapabilityResponse
Get检索配置/状态数据的一次性快照 (pull 模式)。支持 ALL/CONFIG/STATE/OPERATIONAL 类型过滤GetRequest/GetResponse
Set修改设备配置: update (upsert) / replace (先删后建) / delete (删除)SetRequest/SetResponse
Subscribe建立流式遥测会话: ONCE / POLL / STREAM (SAMPLE/ON_CHANGE)SubscribeRequest/SubscribeResponse

Capabilities 示例

gnmic capabilities
gnmic -a 192.168.1.1:57400 --insecure capabilities # Response: gNMI version: 0.10.0 supported models: - openconfig-interfaces, openconfig, 2.5.0 - openconfig-bgp, openconfig, 6.0.0 - openconfig-telemetry, openconfig, 1.0.0 supported encodings: - JSON, JSON_IETF, PROTO, BYTES, ASCII

Set 操作类型

操作描述
Update创建或更新指定路径的配置 (upsert 语义)
Replace替换指定路径的配置 (先删除后创建)
Delete删除指定路径的配置

4. Subscribe 流式遥测机制

sequenceDiagram
    participant C as gNMI Client
    participant D as gNMI Target

    Note over C,D: Subscribe (STREAM + SAMPLE mode)

    C->>D: SubscribeRequest (path + mode + interval)
    D-->>C: SubscribeResponse (sync=true, initial snapshot)

    loop Every 5s
        D-->>C: SubscribeResponse (update)
        Note right of C: counters / rates / health
    end

    Note over C,D: Subscribe (STREAM + ON_CHANGE mode)

    C->>D: SubscribeRequest (path + ON_CHANGE)
    D-->>C: SubscribeResponse (sync=true, initial state)
    D-->>C: SubscribeResponse (update: link down!)
    Note right of C: Event-driven push
    D-->>C: SubscribeResponse (update: BGP peer changed)

4.1 订阅模式对比

模式触发方式典型间隔场景
ONCE单次快照后关闭—等价 Get，通过流返回
POLL客户端主动发起 poll按需客户端驱动采样
STREAM · SAMPLE定时采样推送1s ~ 600s常规监控 / 容量规划
STREAM · ON_CHANGE值变更时推送亚秒级链路状态 / BGP Peer 变更

4.2 ON_CHANGE 在 AI 训练网络的价值

GPU 间 RDMA 通信对丢包极为敏感。gNMI ON_CHANGE 可实时捕获以下微秒级事件，这是 SNMP 轮询无法做到的：

  • PFC (Priority Flow Control) 暂停帧激增 → RoCE 网络拥塞预警
  • ECN 标记异常增长 → 主动降速以避免丢包
  • 缓冲区占用瞬时冲高 → 微突发 (microburst) 检测

6.1 gnmic (官方推荐 CLI)

gnmic Installation & Usage
# Install gnmic curl -sL https://github.com/openconfig/gnmic/releases/download/v0.37.0/gnmic_0.37.0_linux_amd64.tar.gz | tar xz sudo mv gnmic /usr/local/bin/ # Stream subscribe - interface counters every 10s gnmic -a 192.168.1.1:57400 --insecure subscribe \ --path "/interfaces/interface/state/counters" \ --mode stream --stream-mode sample --sample-interval 10s # ON_CHANGE subscribe - BGP session state gnmic -a 192.168.1.1:57400 subscribe \ --path "/network-instances/network-instance/protocols/protocol/bgp/..." \ --mode stream --stream-mode on_change # Set - update interface description gnmic -a 192.168.1.1:57400 set \ --update-path "/interfaces/interface[name=Ethernet1]/config/description" \ --update-value "Uplink-to-Core"

8. AI 时代与 SDN 融合

8.1 gNMI 在 AI 训练网络的价值

  • 亚秒级微突发检测: GPU 间 RDMA 通信对丢包极为敏感，ON_CHANGE 可实时捕获 PFC 暂停帧激增
  • 闭环自动调优: 遥测数据 → AI 分析引擎 → Set() 下发优化策略 → 验证效果
  • 全栈可观测: 从光模块温度到 BGP 路由表，统一 Path 模型
  • LLM-Driven IBN: 模型驱动特性使其成为 LLM 翻译意图到设备配置的首选协议

9. Python 开发实践

pygnmi — Python gNMI Client
from pygnmi import gNMIclient # Connect to device with gNMIclient( target=('192.168.1.1', 57400), username='admin', password='admin123', insecure=True ) as gc: # Capabilities caps = gc.capabilities() print(f"Models: {[m['name'] for m in caps['supported_models']]}") # Get - interface state result = gc.get( path=['/interfaces/interface[name=Ethernet1]/state'], encoding='json_ietf' ) # Set - update interface gc.set( update=[ ('/interfaces/interface[name=Ethernet1]/config/description', 'Uplink-to-Core') ] ) # Subscribe - streaming telemetry subscription = gc.subscribe( subscribe={ 'interfaces': { 'path': '/interfaces/interface/state/counters', 'mode': 'stream', 'stream_mode': 'sample', 'sample_interval': 10000000000 # 10s in ns } } ) for response in subscription: print(response)
