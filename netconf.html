1. 概述与背景

1.1 什么是 NETCONF

NETCONF (Network Configuration Protocol) 是 IETF 于 2006 年首次发布的网络配置管理协议，定义于 RFC 6241，提供安装、修改和删除网络设备配置的标准化机制。使用 XML 编码，通过 SSH (端口 830) 进行安全 RPC 通信。

NETCONF 被业界公认为 "网络配置自动化的基石协议"，它取代了脆弱的 CLI 屏幕抓取 (screen-scraping)，开启了模型驱动的网络可编程时代。

1.2 为什么需要 NETCONF

传统 CLI/SNMP 痛点NETCONF 解决方案
CLI 输出无结构化，脚本脆弱XML 结构化数据，Schema 校验
配置变更无回滚保障候选数据存储 + commit/rollback 事务
SNMP 不支持配置写入edit-config 操作 + 多数据存储支持
多厂商 CLI 语法不兼容统一 YANG 模型驱动的标准化接口
无配置校验validate + confirmed-commit 安全网

1.3 发展里程碑

时间里程碑
2006RFC 4741: NETCONF 1.0 (初始版)
2011RFC 6241: NETCONF 1.1 (当前基础)
2016RFC 7950: YANG 1.1 数据建模语言

3. 核心 RPC 操作

操作描述
<get>获取运行配置和状态数据
<get-config>获取指定数据存储 (running/candidate/startup) 的配置
<edit-config>修改配置: merge / replace / create / delete / remove
<copy-config>复制一个数据存储到另一个
<lock> / <unlock>排他锁定/解锁数据存储
<commit>原子提交候选配置 → 运行配置
<discard-changes>回滚所有未提交的候选变更
<validate>校验候选配置有效性 (dry-run)

edit-config 操作模式

模式语义
merge合并配置 (默认): 新数据并入，冲突时覆盖
replace完全替换: 用新配置替换指定范围的现有配置
create仅创建: 配置不存在则创建，存在则报错
delete删除指定配置项
remove静默移除: 不存在不报错

XML RPC 消息示例

edit-config Request (merge mode)
<!-- NETCONF edit-config RPC --> <rpc message-id="102" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0"> <edit-config> <target><candidate/></target> <config> <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces"> <interface> <name>GigabitEthernet0/0/0</name> <description>Uplink to Core</description> <enabled>true</enabled> </interface> </interfaces> </config> </edit-config> </rpc>

4. 数据存储与 ACID 事务模型

4.1 经典数据存储

数据存储描述
running设备当前活动配置 (正在转发流量)
candidate候选配置暂存区 (可选能力 :candidate)
startup下次启动时加载的配置 (可选能力 :startup)

4.2 事务工作流

NETCONF Transaction Workflow
1. lock(target='candidate') # 排他锁定 2. edit_config(target='candidate') # 修改候选配置 3. validate(source='candidate') # dry-run 校验 4. commit() # 原子提交 candidate → running OR discard_changes() # 回滚所有变更 5. unlock(target='candidate') # 释放锁

4.3 Confirmed Commit (安全网)

远程变更最危险的场景: "把自己锁在外面"。confirmed-commit 提供了超时自动回滚的安全机制：

Confirmed Commit Example
<rpc message-id="103"> <commit> <confirmed/> <confirm-timeout>300</confirm-timeout> <!-- 5分钟超时 --> </commit> </rpc> # 管理员 5 分钟内未发送第二次 commit 确认 # → 设备自动回滚到变更前状态

5. YANG 数据建模语言 (RFC 7950)

YANG 是 NETCONF 配套的数据建模语言，定义配置和状态数据的层次结构、类型约束和语义。

5.1 YANG 关键特性

📋

config false

标记只读状态数据，与配置数据分离

🔗

must 约束

XPath 表达式定义跨节点约束关系

⚡

when 条件

条件性数据节点存在性判断

🧩

augment

扩展现有模型而不修改原文件

🔄

deviation

声明设备对标准模型的偏离

🏷️

标记可选功能模块

6. NMDA 扩展 (RFC 8526)

NMDA (Network Management Datastore Architecture) 将经典数据存储细分为五个逻辑存储，实现了意图配置与实际运行状态的分离：

数据存储描述可写
running运行配置是
intended意图配置 (期望状态)是
operational操作状态 (实际生效状态)否 (只读)
system系统控制的配置否
ephemeral临时配置 (重启后消失)是

NMDA 新增的 <get-data> 操作替代传统的 <get-config> 和 <get>，支持直接按数据存储类型精确查询。

9. Java NETCONF 开发实践 (Apache SSHD)

Java NETCONF Client -- NetconfClient.java
// Java NETCONF client via SSH subsystem import org.apache.sshd.client.SshClient; import org.apache.sshd.client.session.ClientSession; import org.apache.sshd.client.channel.ClientChannel; import java.io.*; public class NetconfClient { private ClientSession session; private PrintWriter out; private BufferedReader in; private static final String END = "]]>]]>"; public void connect(String host, String user, String pass) throws Exception { SshClient client = SshClient.setUpDefaultClient(); client.start(); session = client.connect(user, host, 830).verify(5000).getSession(); session.addPasswordIdentity(pass); session.auth().verify(5000); ClientChannel ch = session.createSubsystemChannel("netconf"); ch.open().verify(5000); out = new PrintWriter(ch.getInvertedIn(), true); in = new BufferedReader(new InputStreamReader(ch.getInvertedOut())); readUntil(); // server hello send("<hello xmlns='urn:ietf:params:xml:ns:netconf:base:1.0'>" + "<capabilities><capability>" + "urn:ietf:params:netconf:base:1.0" + "</capability></capabilities></hello>"); } void send(String xml) { out.print(xml + END); out.flush(); } String readUntil() throws Exception { StringBuilder sb = new StringBuilder(); String line; while ((line = in.readLine()) != null) { sb.append(line).append("\n"); if (line.contains("]]>")) break; } return sb.toString(); } public String getConfig(String source) throws Exception { send("<rpc message-id='101' xmlns='urn:ietf:params:xml:ns:netconf:base:1.0'>" + "<get-config><source><" + source + "/></source></get-config></rpc>"); return readUntil(); } // Transactional config change: lock -> edit -> commit -> unlock public void transactionalEdit(String configXml) throws Exception { send("<rpc><lock><target><candidate/></target></lock></rpc>"); readUntil(); send("<rpc><edit-config><target><candidate/></target>" + "<config>" + configXml + "</config></edit-config></rpc>"); readUntil(); send("<rpc><commit/></rpc>"); readUntil(); send("<rpc><unlock><target><candidate/></target></unlock></rpc>"); readUntil(); } public void close() throws Exception { send("<rpc><close-session/></rpc>"); session.close(); } public static void main(String[] args) throws Exception { NetconfClient c = new NetconfClient(); c.connect("192.168.1.1", "admin", "admin123"); String config = "<interfaces xmlns='urn:ietf:params:xml:ns:yang:ietf-interfaces'>" + "<interface><name>Eth1</name>" + "<description>Uplink</description></interface></interfaces>"; c.transactionalEdit(config); System.out.println(c.getConfig("running")); c.close(); } }
